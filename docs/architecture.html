Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a Python FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Two processes on localhost. The browser runs the frontend; the frontend calls the backend over HTTP.

Data flow

What happens when a user changes a filter on any page.

  1. User changes a filter The filter bar updates shared refs (period, location, category, status) in useFilters.js. They live at module level, so every view sees the same state.
  2. View builds the request The view calls getCurrentFilters() and passes the result to a method in api.js. Values of all are skipped, so no query parameter is sent for them.
  3. Axios sends a GET request For example /api/orders?warehouse=...&category=...&month=Q3-2025 to http://localhost:8001.
  4. FastAPI filters in memory apply_filters handles warehouse, category and status. filter_by_month handles a month such as 2025-09 or a quarter such as Q3-2025, matched against order_date.
  5. Pydantic validates the response Routes declared with response_model return typed, validated JSON.
  6. View renders the result The response is stored in refs (for example allOrders, inventoryItems). Charts, totals and tables are computed properties derived from those refs.

Things worth knowing

Observations from reading the code

  • Missing backend routes. api.js calls /tasks (list, create, delete, toggle) and /purchase-orders (create, fetch by backlog item). main.py defines purchase-order models but no handlers for these paths, so those calls would return 404.
  • Backlog view is not routed. Backlog.vue exists but is not registered in main.js.
  • Hardcoded API address. api.js uses http://localhost:8001/api directly, so it only works locally as written.
  • Open CORS. The backend allows all origins, which suits local development only.
  • No persistence. Data is read from JSON at startup, and changes are lost on restart.
  • No authentication on any endpoint.
